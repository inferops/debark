Foundations #

Two stylesheets, no build step, no npm, no webfont, no network request. tokens.css defines every value; components.css spends them. A screen author should never need to open either.

Theming. Every colour is defined once, on bare :root, as light-dark(<light>, <dark>). color-scheme is the switch: light dark on :root follows the system, and :root[data-theme="light"] / :root[data-theme="dark"] pin it, so an explicit choice wins in both directions. Use the toggle above; “System” removes the attribute entirely. The hex pairs in the swatch tables below are the two arms of each light-dark(). The three elevation tokens are the exception — light-dark() switches colours, not lengths — and keep --shadow-1-dark…-3-dark counterparts; see README §3.

Brand / identity — quarantined

--color-accent is not amber and must not become amber. The accent carries the selected-row tint, the focus ring, the checked box, the primary fill, badges and the progress fill, constantly, next to 60,000 rows of text. Brand amber is 1.96:1 on the light brand ground, which is why it is quarantined as decorative wherever this brand is applied; the identity accent that does carry meaning is the desaturated brown --color-brand-accent, at 4.84:1 / 5.12:1.

Brand hue and semantic hue never meet. Brand amber against --color-warning is 1.56:1 / ΔE 11 (light) and 1.59:1 / ΔE 12 (dark) under simulated deuteranopia — the same colour to a reader. So brand tokens appear only inside .df-brand and never beside a status.

Monospace is load-bearing

Package names, versions, architectures, paths, digests and NDJSON all render in --font-family-mono. Never set a version or a digest in the UI stack — column alignment and unambiguous 0/O and 1/l/I are the whole point.

Density

--row-height: 32px is a contract with the virtualiser. It multiplies this number to size the scroll spacer; a row box that does not match it makes the list tear while scrolling. Keep it a round number.

Grouping — boxed lists, not cards #

This is the most important section on the page. A bordered .df-panel on a differently-shaded canvas, used as the default way to group anything, is what made this app read as an admin dashboard: peripheral vision counts rectangles before it reads a label, and one screen stacked seven of them in a single column with each title inside its box. Gating — the aria-disabled idiom #

A gated flow has more “you cannot do this yet” states, not fewer. A disabled control is out of the tab order, so a keyboard or screen-reader operator never meets it and is never told the one useful sentence on the screen: why.

Wrong

Unreachable by Tab. The operator learns nothing.

Right

Choose at least one package first.

Focusable, hoverable, announced. Use .df-gate-reason when the sentence should be on screen and .df-live when it should only be announced — both are valid aria-describedby targets, because the accessible-description computation includes a directly-referenced node even when it is hidden. The handler refuses the click, rewrites the live region so it is re-announced, and moves focus to the control that will unblock it.

Accessibility #

  • Focus. Every interactive element has a visible ring. outline: none appears twice in the library and never without a replacement: on :focus:not(:focus-visible), which drops the fallback ring for pointer focus on engines that support :focus-visible (the next rule re-applies it for keyboard); and on .df-search__input, because the ring is drawn on the wrapping .df-search via :focus-within so the leading icon sits inside it. A full-width list row draws its ring inset, because the list clips an outset one. Tab through this page to check.
  • Contrast. 146 foreground/background pairs are measured in both themes — 292 measurements — and all pass. Body text clears 4.5:1, borders and non-text clear 3:1. Six of the 146 are informational with no floor (the focus halo against the fill it sits on: the halo is a spacer, not the indicator). Every number is in README.md §7 and was recomputed from tokens.css, not carried over.
  • Colour is never the only signal. Banners pair a hue with a distinct icon shape and a title. Selected rows add a leading rule and a checked box. Selected tabs add weight and an underline. Indeterminate checkboxes draw a bar rather than a tick. The “colour removed” row in the Status section shows the result.
  • Colour-vision deficiency. The alert colours were solved against a dichromacy simulation rather than picked by eye, and the solve was re-run for this palette rather than quoted. Warning and danger hold 2.46:1 / ΔE 25 (light) and 2.38:1 / ΔE 22 (dark) apart under simulated deuteranopia. Details, the brand-hue collision numbers and the tritanopia caveat are in README.md §8.
  • Reduced motion. Every duration is a token and every token collapses under prefers-reduced-motion: reduce; looping animations stop outright. That is why a busy control must always carry a text label — the spinner alone is not permitted to be the only indication.
  • High contrast, two queries for two platforms. Both files hand the palette back to the OS under forced-colors: active rather than fighting it — and that query is Windows/WebView2 only. Measured on WebKit2GTK: it never matches, not even under GTK’s own HighContrast theme, and forced-color-adjust is unimplemented. What Linux signals is prefers-contrast: more, and tokens.css answers it by promoting the two decorative hairlines that sit below 3:1 — --color-border-subtle and --color-brand-border — to colours §7.2 already measures above it, and by drawing the focus ring 3px instead of 2px. No new colour is introduced, so no measured pair moves. README.md §7.4 has the 52 pairs.
  • Hit targets. --hit-target-min is 24px and the chip remove button fills it even though its glyph is 10px.
